# 音视频转译（本地初版）

本功能已包含于 `v0.2.0-preview.1` 完整离线预览包。已完成 Release 编译和程序合成英文音频的 GPU 英语识别、Hy-MT2 流式翻译及时间戳 TXT 保存检查；完整界面、其他媒体格式和跨设备安装仍待验收。

## 使用

1. 打开“音视频转译”，选择单个本地音频或视频。文件筛选包含 MP3、WAV、M4A、FLAC、OGG、MP4、MKV、MOV、AVI、WebM 等；实际支持取决于语音环境内 PyAV/FFmpeg 的解码器。不支持无音轨、加密/DRM 或损坏文件。
2. 选择文本保存目录。默认是 Windows 文档目录的 `Glimpse/Transcripts`。
3. 默认“仅 GPU · 识别与翻译”；可改为“仅 CPU · 识别与翻译”。GPU 模式要求兼容 NVIDIA CUDA，同时约束 faster-whisper 和 Hy-MT2；失败不会悄悄回退 CPU。VAD、媒体解码和重采样使用 CPU。CPU 模式两种模型均使用 CPU。
4. 点击“开始转译”。界面显示当前阶段、已识别位置/总时长、实际会话用时，以及最近一块识别/最近一段翻译耗时。识别位置可能领先中文翻译；模型计算尚未开始时耗时为 0。总时长无法获取时使用不定进度。会话用时包含加载、暂停、保存及恢复；耗时不写入 TXT。
5. “暂停”在当前识别块或翻译片段完成并保存后生效，“继续”保留当前模型及位置。“取消并保存”中断当前运算，保存已有定稿译文及已提取英文；未完成翻译以标记说明。流式半句不会成为正式译文。
6. 完成后可“打开文本”“另存为”或“打开目录”。显示预览只保留最近一部分内容，完整结果在 TXT 文件内。

语音环境及英语识别模型复用“实时字幕 → 语音模型与字幕设置”的 Python/模型路径；翻译复用偏好设置内的本地 Hy-MT2 GGUF 及 CPU/GPU 运行时。首次配置可参考 [实时字幕说明](LIVE_CAPTIONS.md)。这些路径无需在两个页面重复配置，文件转译不会调用在线 API。

## 音轨、分段与时间戳

视频优先取带默认标记的音轨，否则取第一条音轨；不会识别视频画面、麦克风或其他应用声音。音轨编号及语言标记写入记录，识别语言固定为英文，不自动切换其他语言。

使用现有 Python 语音环境的 PyAV 解码，重采样为 16 kHz 单声道，无需额外安装 FFmpeg 命令行工具。只允许本地文件协议；模型使用已有本地文件，不下载资源。

音频分块读取，每块上限约 30 秒，优先在后半段的停顿处切开，随后使用 VAD 和语音模型分段。持续讲话无合适停顿时仍会在块边界切分，可能影响跨边界句子的完整性。过长英文段按同次识别产生的词时间戳进一步分段，避免超出翻译长度限制。文件处理不使用同传的约 3 秒提交门槛。

起止时间相对原文件起点，保留所选音轨的起始偏移及解码帧时间戳中的间隙；VAD 分段结果映射回音频位置。若源文件缺失时间戳，则按连续采样位置计算。时间精度及各格式同步情况待实测。

## 输出与恢复

输出 UTF-8 TXT，默认文件名 `原文件名_中英翻译.txt`；重名使用 `_2`、`_3` 等后缀，保留已有文件。文本包含源文件、设备/音轨事件及英文/中文时间段，不保存音频副本。

```text
[00:01:12.350 → 00:01:16.820] #0001
EN: Thursday's class is online or physical?
ZH: 星期四的课是线上还是线下？
```

识别英文后排入后台写入队列，完整中文完成后按序更新，同一个写入器使用临时文件替换原记录。片段及块边界等待保存检查点；写入失败会停止并明确报告，不能保证故障磁盘上的保存。文件导入有意在检查点等待磁盘，字幕预览及写入仍通过独立通道传递。

本次任务第一次失败先保存，再清理并重启相关模型进程一次；恢复先翻译已确认但未完成的英文，再从已识别块的末尾继续，继续使用原 TXT 和近期最多 4 组、总计 1000 字符的双语上下文。第二次失败停止并保存。重启语音进程会重新解码并丢弃此前采样以恢复精确位置，长文件恢复会有额外等待，但不会再次识别已确认的块。

进度恢复只限当前任务的一次自动重启；退出应用或取消后，第一版不提供重新导入 TXT 的跨次断点续传。正常取消会等待保存，强制结束应用仍可能丢失尚未写入的文字。

实时字幕与文件转译在整次操作（包括加载、暂停、恢复）中互斥；本地工作台翻译也等待语音任务停止后再使用。完成、取消或失败后释放语音模型和占用标记，并恢复原本的 Hy-MT2 常驻策略。不会修改用户的工作台设备选择。

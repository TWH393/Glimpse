# 应用实时字幕（本地初版）

本功能已包含于 `v0.2.0-preview.1` 完整离线预览包。已通过 Release 编译、6 个真实 GPU ASR 回归场景及文件识别/翻译检查；真实应用采音与完整桌面界面仍待验收。

## 使用

1. 在 Visual Studio 打开 `Glimpse.slnx`，编译并运行项目。
2. 打开“实时字幕”，从音量合成器同类的输出音频会话中选择应用，或主动选择“全局识别 · 所有应用声音”。列表包含音频活动与暂时空闲的会话，显示图标、会话名称和 PID，不再根据窗口筛选；未出现的应用先播放声音，再刷新或重新展开下拉框。浏览器按整个进程树捕获，不区分标签页。全局识别包含其他应用及系统声音，排除 Glimpse 自身及其子进程的输出，不直接采集麦克风。初版两种方式均需要 Windows 11。
3. 展开设置，确认独立 Python 和本地模型路径。“同传仅 GPU”默认开启，同时要求语音识别和 Hy-MT2 在 GPU 上运行，不允许回退 CPU，优先于偏好设置中的仅 CPU/自动选择；VAD 仍为轻量 CPU 检测。取消勾选后恢复原识别设备选择及翻译设备规则。设备变更下次会话生效。同传翻译始终使用本地 Hy-MT2，不使用在线引擎。
4. 点击“开始字幕”。加载模型及 VAD 后才开始采音，音量条用于判断是否捕获到了声音。英文草稿和稳定结果复用同次解码，稳定前缀提前提交，未稳定部分继续等待；约 3 秒缓冲后主动提交。中文字幕通过 SSE 流式显示，游标表示临时结果，完成后才定稿并保存。
5. 在透明字幕窗中拖动标题或缩放，或在控制页调整字号、底板不透明度和中英双语。锁定后鼠标穿透，`Ctrl+Alt+L` 或托盘“实时字幕”菜单可解锁。快捷键被占用时使用托盘菜单。
6. 暂停会停止音频客户端，完成之前已采集的片段；恢复不补录暂停期间的声音。“停止并保存”会停止采音、请求语音进程处理尾段，并等待已确认英文翻译，最后关闭语音进程、隐藏字幕和恢复模型策略。

记录默认保存到 Windows 文档目录下的 `Glimpse/Sessions/`，可直接打开、打开文件夹或另存为。文件名为 `时间_应用名.txt`，例如 `2026-10-23_204530_Microsoft Edge.txt`；全局识别为 `2026-10-23_204530_全局声音.txt`。不再在文件名中加入 PID 或随机串。同一秒同一应用重名时依次添加 `_2`、`_3`，保留已有记录；非法文件名字符会移除。

每次会话独立 UTF-8 TXT，内容包含应用、来源 PID（或全局范围）、起始时间、原始音频时间戳、配对英文/中文。耗时仅在界面显示，不写入记录。确认英文后排入后台写入队列，正式中文完成后按顺序更新；字幕显示不等待磁盘写入。仅保存定稿译文，临时中文不会作为完整结果写入。单一后台写入器使用临时文本替换并刷新磁盘。首次失败、停止、打开记录或另存为会等待此前写入完成；异常强制终止仍可能丢失尚在队列中的文字，`.tmp` 可能留下可恢复内容。没有音频文件。

## 失败恢复与耗时

同一次点击“开始字幕”最多自动重启一次，失败计数不会在恢复成功后清零：

1. 识别、翻译、采音、进程通信或队列超限首次失败：把原因写入页面文本框和会话文件，丢弃流式半句、停止本轮进程，等待后台保存检查点完成，再重启识别与翻译进程。
2. 重启继续使用同一个 `时间_应用名.txt`、原始时间轴和最近上下文；已经确认但尚未完成翻译的英文会重新排队，不重复创建已成功的译文。
3. 再发生失败：把第二次原因和停止原因写入文本框与记录，停止采音/模型任务，标记未完成译文并等待保存，不继续循环重启。重新手动点击开始才建立新会话和新的失败预算。

恢复间隙的声音没有录音，无法补识别，会在记录中说明。磁盘写入错误导致无法完成检查点时不能承诺保存成功，会直接报告并停止，避免错误显示“已保存”。用户主动停止时不触发自动重启。

页面实时显示：分句收集时长、识别计算时长、音频消息排队、翻译排队、翻译首字、翻译总计、距原句末尾到首字/定稿的延迟。计时来自实际音频位置和 Stopwatch/perf_counter，不是固定估算值。分句收集表示本轮解码缓冲的音频长度；音频排队显示当前片段观测到的最大消息等待（含父进程发送队列）。识别时长不包含前面的分句收集；距句末延迟在发出显示事件时采样，不包含随后窗口渲染的一帧耗时。指标仅用于实时显示，不保存到 TXT；重启后的重译仍从原始句末计算总延迟。页面支持纵向滚动，展开设置后可向下查看字幕记录和操作按钮。

约 3 秒是音频缓冲提交门槛，不是端到端延迟保证，实际仍会加上识别、排队和翻译时间。

## 实现边界

- Windows WASAPI process loopback：单应用包含目标进程及子进程；全局模式显式使用排除 Glimpse 进程树的输出回环，涵盖其他输出流。两种模式均转换为 16 kHz 单声道 PCM16；时间戳优先使用音频包 QPC，时钟无效时使用采音时钟。
- 应用列表通过 Core Audio 枚举所有可用输出设备上的非过期音频会话，包含暂时空闲的会话。浏览器/Electron 的同名进程树及常见 WebView 辅助进程会合并到应用；音量合成器可能有不同的名称或分组，尚未实测完全一致。系统声音包含在全局项中，暂不提供仅系统提示音的独立捕获。应用退出或枚举失败时不自动切换全局，刷新后原应用消失会清空选择。
- faster-whisper 1.2.1 / CTranslate2 4.8.3 / Distil-Large-v3.5 CT2；GPU 使用 FP16，取消仅 GPU 后 CPU 使用 INT8。仅 GPU 下初始化/推理失败必须进入上述恢复流程，不能回退 CPU；关闭仅 GPU 时沿用原有自动/优先 GPU 的 CPU 后备策略。
- VAD 每约 0.2 秒检查，约 0.3 秒静音判定，识别约每新增 1 秒音频执行一次；相邻结果的稳定前缀提前提交，避免在常见虚词后主动截断，约 3 秒缓冲主动提交。边缘保留约 0.16 秒重叠，按单词时间戳去重；尾段缓冲未变化时复用缓存结果，不为草稿和定稿额外重复解码。仍属于滚动片段识别，不是原生逐字流式模型；更短片段的准确率和实际延迟待用户验证。
- 检测到语音但识别为空时不推进时间轴、不清除缓冲，先等真实音频上下文补足到约 2 秒；约 3 秒提交时保留距缓冲末尾约 0.3 秒内的词尾。重复词同时比较词形及时间重叠，避免重解码的时间戳漂移导致重复提交。单独短句在停止、暂停、时间轴中断或音频包停止到达后会对空结果进行一次较完整重试（临时补尾部静音、beam size 3，保留置信度筛选）；补充的静音不进入原始时间戳。重试仍无结果则明确报错，进入会话恢复流程。正常草稿/定稿仍共用缓存，额外解码只用于空结果恢复。
- 每条译文只参考最近最多 4 组双语，合计最多 1000 字符；自动重启保留本次已确认上下文，真正停止后清空，不自动读取其他会话文件。
- 会话持有 Hy-MT2 使用权，暂停自动闲置/显存压力卸载。工作台/划词不并发占用同一 Hy-MT2 模型；设备或模型路径变更在会话后应用。停止后恢复原性能/节能模式，语音模型不常驻。
- 音频消息、识别消息及翻译队列均有限制；积压超过限制时停止采音并报告，已确认英文保留。尚未识别的内存音频在异常退出时无法恢复，不能保证故障情况下记录完整。
- 停止时给语音尾段最多 30 秒、翻译队列最多 90 秒；超时会取消任务并标记。已完成文字尽量保留，正常关闭程序也会关闭所属子进程。
- 不加额外降噪、不区分说话人、不朗读译文，不保存录音。所有模型均从本地读取，语音工作进程禁用 ORT 遥测和 Python socket 联网。

### 短句回归检查

本机使用程序合成的英文 WAV 在 NVIDIA CUDA 上完成了 6 个真实 ASR 回归场景：开头短句后接长句、单独短句后停止、短句后暂停、音频时间轴间断、纯静音，以及无后续音频包时自动提交。开头的 `Hello.` 已保留，结果检查包含文字完整性和片段时间顺序。这不代表已验证真实应用采音、窗口交互或所有短句的识别准确率。

对应脚本：`tests/live_asr_regression.py`。使用语音环境的 Python，传入 `--sample`（内容为 `Hello. This is a local translation test. The class will be online on Thursday.` 的英文音频）及 `--model`；检查日志默认保存在 `artifacts/validation/live-asr-regression/`，不提交 Git。

## 环境与模型

本机已准备 `.runtime/speech-env/` 和 `models/speech/distil-large-v3.5/`，不提交 Git。其他源码环境可运行：

```powershell
./tools/install_speech.ps1
```

安装脚本使用 `worker/speech-requirements.lock.txt` 的精确版本及下载哈希，下载固定修订的模型并记录文件 SHA-256，不执行识别测试。模型约 1.51 GB，CUDA/cuDNN 及其他依赖另占空间。CPU 也使用该环境和同一模型；目前未附带更小的 CPU 专用模型。语音环境和模型已包含于 `v0.2.0-preview.1` 完整离线包。

本次低延迟、流式译文、后台写入和一次恢复改动尚未编译、采音或推理实测。待用户验收：稳定前缀有无重复/漏词、3 秒分段准确率、SSE 中文展示、仅 GPU 禁止回退、首次故障自动重启和第二次停止保存、后台写入顺序/检查点、时间指标、应用隔离、暂停/恢复、尾段处理、游戏帧率及长时间会话。
